# 스크린리더 수동 테스트 계획 (NVDA / VoiceOver / TalkBack)

> 목적: 자동 감사(`npm run a11y`)가 잡지 못하는 실제 스크린리더 동작을 사람이 확인하기 위한 절차.
> 주의: 자동 도구는 접근성 문제의 약 30~40%만 탐지한다. 이 문서는 배포 전 **사람이 직접** 수행해야 한다.

## 1. 환경

| 스크린리더 | OS | 브라우저 | 비고 |
|---|---|---|---|
| NVDA | Windows 10/11 | Chrome, Firefox | 무료 |
| VoiceOver | macOS | Safari | 기본 내장 |
| VoiceOver (iOS) | iOS | Safari | 기본 내장 |
| TalkBack | Android | Chrome | 기본 내장 |

사전 준비:

```bash
npm.cmd run build:web
npx serve dist
# 또는 개발 모드: npm.cmd run web
```

## 2. 공통 확인 항목

- [ ] 페이지 로드 시 **제목**이 낭독된다.
- [ ] `본문으로 건너뛰기` 링크가 첫 Tab에서 나타나고, 활성화하면 본문으로 이동한다.
- [ ] 모든 인터랙션에 **역할(role)·이름(name)·상태(state)** 가 낭독된다.
- [ ] Tab/Shift+Tab 순서가 시각적 순서와 일치한다.
- [ ] 포커스 표시가 항상 보이고, 고정 요소에 가려지지 않는다.
- [ ] 버튼/보기의 터치 타겟이 최소 24×24 CSS px 이상이다.
- [ ] 동적 변경(문항 이동, 저장 완료, 위험 결과)이 **라이브 리전**으로 낭독된다.
- [ ] 키보드 트랩이 없다.
- [ ] 200% 확대·320px 폭에서 내용이 잘리지 않는다.
- [ ] 색만으로 의미를 전달하지 않는다(텍스트 라벨 병행).

## 5. 릴리스 승인용 수동 증빙

실제 장비와 담당자의 확인 뒤에만 [수동 접근성·실기기 검증 증빙 레지스트리](operations/a11y-device-evidence.md)에 기록합니다. 이 계획의 체크박스만 변경해서는 릴리스 준비도 게이트를 통과할 수 없습니다.

필수 범위는 NVDA, VoiceOver, TalkBack, 320px 폭, 200% 확대, 실제 전화 앱, 오프라인 위기 안내입니다. 기록할 내용은 테스트 일자, 역할(개인명 제외), OS·브라우저·스크린리더/기기 버전, 시나리오별 실제 동작, 발견 이슈의 조치 식별자와 재검증 결과입니다. 개인 건강정보·설문 응답·통화 상대방 정보는 기록하지 않습니다.

`npm.cmd run manual:packet`은 현재 범위 해시, 7개 시나리오별 확인 항목·통과 기준, 비식별 기록 형식과 “증빙 아님” 고지를 출력합니다. 실제 시험 전 준비 자료로만 사용합니다.

`npm.cmd run manual:check`은 형식·누락·최신 실패·180일 유효기간·현재 접근성/위기 범위 해시만 검사합니다. 이 문서나 자동 검사는 임상 타당화·법무 검토·실제 접근성 적합성 판단을 대신하지 않습니다.

## 6. 알려진 한계

- 이 저장소에는 실제 NVDA/VoiceOver/TalkBack 실행 결과가 포함되어 있지 않다. 자동 감사와 코드 수준 점검만 완료된 상태다.
- RN Web은 DOM 구조가 네이티브와 다르므로, 네이티브 앱 접근성은 별도 기기 테스트가 필요하다.
- 스크린리더별 낭독 차이는 실제 기기에서만 확인할 수 있다.
