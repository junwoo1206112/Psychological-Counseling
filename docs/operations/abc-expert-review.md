# A/B/C 독립 전문가 교차검증 기록 템플릿

> 상태: **내부 근거 검토 완료, 실제 독립 전문가 승인 미완료**  
> 목적: 앱의 선별·위기 안내·프라이버시 설계를 서로 다른 전문 관점에서 검토하고, 실제 배포 전 독립 검토 증빙을 남깁니다.

## 1. 역할과 경계

| 역할 | 검토 범위 | 앱이 현재 제공하지 않는 것 |
|---|---|---|
| A — 임상·심리측정 | PHQ-9/PHQ-A/GAD-7/ASQ의 사용 범위, 결과 문구, 번역·타당화 | 진단, 치료, 한국어판 임상 타당화 완료 선언 |
| B — 위기·자살예방 | 급성/비급성 분기, 위기 자원, BSSA 후속 절차, 연결 실패 | 자동 구조, 자동 보호자 통보, 앱 내 BSSA |
| C — 구현·프라이버시·법무 | 데이터 최소화, 저장·삭제, 접근성, 배포·규제 게이트 | 서버 PII 저장, 무동의 기관 전송, 법적 분류 확정 |

## 2. 이번 근거 기반 교차검증

| 논점 | A 판단 | B 판단 | C 판단 | 합의된 구현 결정 |
|---|---|---|---|---|
| PHQ/GAD 결과 | 자가보고는 임상가 확인 전 진단이 아님 | 낮은 점수도 위기 부재 보장 아님 | 점수·밴드만 최소 저장 | 진단·확률·복합 위험점수 미표시 |
| ASQ 양성 | 추가 평가 필요 | 급성은 즉시 도움, 비급성도 후속평가 필요 | 앱이 BSSA를 수행할 수 없음 | crisis-first + 109/전문가 안내 + 운영 게이트 |
| 한국어 문항 | 타당화 전 임상/상업 사용 불가 | 이해도와 연령 고려 필요 | 버전·해시·번역 상태 기록 | 영문 원문 기준, `unofficial` 유지 |
| 후속연결 | 임상 책임과 BSSA 필요 | 본인 동의·대체 경로 필요 | PII·계약·운영 체계 필요 | 자동 의뢰 미도입, 프로토콜 증빙 전 차단 |
| 저장·전달 | 임상 기록으로 오인 금지 | 위기 중에도 자원 접근 가능 | 로컬 최소 저장·삭제·예외 처리 | 무백엔드·응답 로그 없음·세션 최소화 |

## 3. 근거

- [PHQ Screeners Terms](https://www.phqscreeners.com/terms): 자가보고 응답은 임상가가 확인하고 최종 진단은 임상 근거로 해야 한다고 설명합니다.
- [NIMH ASQ Toolkit](https://www.nimh.nih.gov/research/research-conducted-at-nimh/asq-toolkit-materials): ASQ 양성 뒤 훈련된 임상가의 BSSA를 안내합니다.
- [식품의약품안전처 안내](https://www.mfds.go.kr/brd/m_1060/view.do?seq=15629): 디지털의료제품 법령 자료의 최신 확인 근거입니다.
- [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage): 탭 단위 저장과 정책상 저장소 접근 예외의 기술 근거입니다.

## 4. 실제 독립 검토 증빙

실제 검토 전에는 아래 표에 `PASS`를 기록하지 않습니다. 검토자 성명·연락처·자격증 번호·환자 정보는 이 저장소에 넣지 않습니다. 접근 통제된 내부 기록의 비식별 식별자와 검토 일자만 기록합니다.

검토 요청 전 `npm.cmd run abc:packet`을 실행해 현재 후보 범위 해시와 역할별 질문을 전달합니다. 이 출력은 검토·승인·임상 평가 결과가 아닙니다.

### 배포 후보 범위 해시

아래 값은 핵심 사용자 화면·문항·오프라인 위기 안내·패키지 구성을 합산합니다. 실제 검토 뒤에만 현재 값으로 바꾸며, 값이 달라지면 재검토가 필요합니다.

- 배포 후보 범위 해시: `기록 전`

### 기록 규칙

- ID: `ABC-YYYYMMDD-설명자` 형식이며 날짜는 기록일과 같아야 합니다.
- 범위: `SCREENING-CONNECTION-STATIC-WEB`를 정확히 적습니다.
- 결과: `PASS` 또는 `FAIL`만 사용합니다. 같은 날짜에 충돌한 기록은 `FAIL`이 우선하며, 최신 유효 `PASS`는 90일 이내여야 합니다.
- 증빙 식별자: 접근 통제된 의견서·회의록·승인 기록의 비식별 식별자만 적습니다.

| 기록 ID | 기록일 | 검토 역할 | 단계 | 범위 | 결과 | 외부 증빙 식별자 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

| 단계 | 필요한 독립 검토 |
|---|---|
| `A-CLINICAL-PSYCHOMETRIC` | 선별도구·번역 상태·결과 문구·타당화 한계 |
| `B-CRISIS-PREVENTION` | 급성/비급성 경로·위기 자원·후속평가 한계 |
| `C-IMPLEMENTATION-LEGAL` | 데이터 최소화·접근성·배포·규제 경계 |
| `RESOLUTION-APPROVAL` | 충돌·잔여 위험·배포 조건을 책임자가 검토한 기록 |

`npm.cmd run abc:evidence:check`은 형식·기한·범위 해시만 검사합니다. 실제 전문가의 독립성·자격·검토 품질·승인 사실은 사람이 확인해야 합니다.

## 5. 검토자에게 확인받을 질문

1. 선별 결과와 위기 분기가 진단·치료 주장으로 읽히지 않는가?
2. ASQ 양성 및 급성 신호에 대해 실제 조직의 BSSA·응급·후속 절차가 충분한가?
3. 번역 타당화 전 배포·표시·마케팅 범위가 적절히 제한되어 있는가?
4. 데이터 최소화, 동의, 삭제, 보관, 사고 대응이 실제 운영과 법적 의무에 부합하는가?
5. 남은 위험과 배포 전 충족 조건을 문서로 승인했는가?
