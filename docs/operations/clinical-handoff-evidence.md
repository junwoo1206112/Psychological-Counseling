# 임상 후속연결 운영 증빙 레지스트리

> 상태: **실제 운영 미완료**. 이 템플릿은 기관이 ASQ 양성 또는 앱의 위기 신호 뒤 실제 후속연결을 제공하려 할 때의 운영 증빙을 기록합니다. 현재 공개 앱은 자가 선별·위기 자원 안내만 제공하며 BSSA, 진단, 치료, 예약, 자동 구조, 자동 의뢰를 수행하지 않습니다.
> 이 저장소에는 임상가·직원의 개인 정보, 자격번호, 환자·상담·설문·연락처 정보를 기록하지 않습니다. 접근 통제된 기관 운영 기록의 비식별 식별자만 남깁니다.

## 운영 경계

- ASQ 양성 뒤 BSSA는 훈련된 임상가가 수행해야 하며, 앱의 점수·라우팅은 BSSA나 처분 결정을 대체하지 않습니다.
- 급성 신호는 결과보다 위기 안내가 우선이며, 앱은 119·112·109 등 즉시 도움 경로를 안내하지만 사용자를 추적하거나 외부에 자동 통보하지 않습니다.
- 기관으로의 정보 전달은 명시적 동의 후에만 가능하며, 동의 거부·철회와 연결 실패 시에도 앱의 위기 자원 안내는 제공됩니다.
- 109 상담에서 지역 기관 연계가 필요할 때도 본인 동의가 전제됩니다. 기관별 법률·임상 지침과 실제 책임 체계는 별도로 승인해야 합니다.

## 운영 범위 해시

아래 값은 핵심 앱 범위와 `clinical-handoff-protocol.md`를 함께 반영합니다. 실제 운영 승인 뒤에만 현재 값으로 바꾸며, 앱 또는 프로토콜이 바뀌면 새 운영 검토를 요구합니다.

- 운영 범위 해시: `기록 전`

## 기록 규칙

- ID: `HANDOFF-YYYYMMDD-설명자` 형식이며 날짜는 기록일과 같아야 합니다.
- 역할: 개인명 대신 역할만 기록합니다(예: `임상 운영 책임 역할`, `위기 대응 책임 역할`, `개인정보 검토 역할`).
- 범위: `OPTIONAL-CLINICAL-HANDOFF`를 정확히 적습니다. 현재 공개 앱은 이 운영 범위를 활성화하지 않습니다.
- 결과: `PASS` 또는 `FAIL`만 사용합니다. 최신 유효 기록이 `PASS`이고 90일 이내여야 합니다. 같은 날짜의 충돌은 `FAIL`이 우선하며, 존재하지 않거나 미래인 날짜는 유효하지 않습니다.
- 증빙 식별자: 기관 승인서·훈련/감독 확인·연락망/근무표·동의서 템플릿·사고 대응 절차·모의훈련 보고서의 비식별 식별자만 기록합니다.

| 기록 ID | 기록일 | 검토 역할 | 단계 | 범위 | 결과 | 외부 증빙 식별자 |
|---|---|---|---|---|---|---|

## 필수 운영 단계

| 코드 | 확인할 최소 내용 |
|---|---|
| `OWNERSHIP` | 임상 운영 책임·대체 책임·운영 시간·연락 경로 |
| `BSSA-TRAINING` | ASQ 양성 후 BSSA 담당 직군, 훈련·감독·가용 시간 |
| `ACUITY-PATHWAY` | 급성/비급성 분기, 시간 기준, 야간·휴일 대체 경로 |
| `CONSENT-DATA` | 명시적 동의, 최소 전송, 거부·철회, 보관·파기와 접근 통제 |
| `FAILURE-INCIDENT` | 연결 실패·담당자 부재·사고·운영 중단의 사용자 안내와 내부 보고/재검토 |
| `GO-LIVE-APPROVAL` | 실제 기관·임상·법무 책임자의 배포 조건·남은 위험·재검토 기한 승인 |

## 배포 전 확인

- [ ] 여섯 단계의 최신 유효 기록이 모두 `PASS`이고 90일 이내다.
- [ ] 운영 범위 해시가 현재 앱·운영 프로토콜과 일치한다.
- [ ] 실제 운영 기관이 NIMH ASQ 후속평가 원칙과 현지 위기 경로를 검토했다.
- [ ] 기록에 개인·환자·상담·설문 정보가 포함되지 않았다.

`npm.cmd run clinical:handoff:check`은 기록 형식·단계·기한·운영 범위 해시만 검사합니다. 실제 BSSA 역량, 기관 계약, 임상적 적절성, 법률상 의무, 운영 가용성이나 승인 사실은 자동으로 증명하지 않습니다.
