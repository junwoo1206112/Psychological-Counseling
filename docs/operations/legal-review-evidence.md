# 법무·규제 검토 증빙 레지스트리

> 상태: **실제 법무·규제 검토 미완료**. 이 문서는 선별+전문가 연결 앱의 배포 전 검토 증빙을 기록하는 템플릿이며 법률 자문, 식약처의 제품 분류, 허가·인증, 개인정보 적법성 판단을 대신하지 않습니다.
> 검토자 이름·연락처·자격번호, 사용자 건강정보·설문 응답·상담 기록을 이 저장소에 기록하지 않습니다. 접근 통제된 내부 의견서·계약·승인 기록의 비식별 식별자만 남깁니다.

## 현재 제품 범위

- 앱은 우울·불안·자살 위험의 **선별 + 전문가 연결 안내**이며 진단, 치료, 예방 효능, 자동 구조, 자동 의뢰, AI 자유대화 상담을 제공하지 않습니다.
- 서버·분석 SDK·응답 로그·PII 수집은 없고, 선택된 기기 내 저장만 제공합니다.
- PHQ-9·PHQ-A·GAD-7 한국어 문항은 `unofficial` 상태이고, ASQ는 NIMH 공식 한국어판을 사용합니다.
- 법령·지침은 변경될 수 있으므로, 실제 검토자는 검토일 현재의 원문을 다시 확인해야 합니다.

## 배포 후보 범위 해시

아래 값은 핵심 화면·문항·오프라인 안내·패키지 구성을 합산한 값입니다. 실제 검토 뒤에만 현재 값으로 바꾸고, 변경된 값은 새 검토를 요구합니다.

- 배포 후보 범위 해시: `기록 전`

## 기록 규칙

- ID: `LEGAL-YYYYMMDD-설명자` 형식이고 날짜는 기록일과 같아야 합니다.
- 역할: 개인명 대신 역할만 기록합니다(예: `외부 법무 검토`, `개인정보 책임 역할`, `규제 검토 역할`).
- 범위: `SCREENING-CONNECTION-STATIC-WEB`를 정확히 적습니다. 기능·배포 구조가 달라지면 검토를 다시 받습니다.
- 결과: `PASS` 또는 `FAIL`만 사용합니다. 최신 유효 기록이 `PASS`이고 90일 이내여야 합니다. 같은 날짜의 충돌은 `FAIL`이 우선하며, 존재하지 않거나 미래인 날짜는 유효하지 않습니다.
- 증빙 식별자: 접근 통제된 의견서·분류 검토·개인정보 영향 검토·라이선스 확인·운영 승인 문서의 식별자만 기록합니다.

| 기록 ID | 기록일 | 검토 역할 | 단계 | 범위 | 결과 | 외부 증빙 식별자 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## 필수 검토 단계

| 코드 | 확인할 범위 |
|---|---|
| `PRODUCT-CLASSIFICATION` | 사용목적·표현·기능을 기준으로 의료기기/디지털의료제품·웰니스 관련 검토 필요성과 다음 조치 |
| `CLAIMS-REVIEW` | 진단·치료·예방·효능·정확도·위험확률 주장 금지 및 사용자 문구 검토 |
| `PRIVACY-REVIEW` | 무백엔드·기기 내 선택 저장·동의·삭제·향후 데이터 처리 변경 시의 조건 |
| `INSTRUMENT-LICENSE` | 영문 원문·한국어 번역·ASQ 사용 범위·출처·재배포 고지 검토 |
| `CRISIS-OPERATIONS` | 위기 번호·자동 구조 부재·BSSA/기관 연계의 운영 책임과 한계 |
| `DEPLOYMENT-APPROVAL` | 남은 위험·배포 조건·재검토 기한·책임자 승인 |

## 배포 전 확인

- [ ] 여섯 단계의 최신 유효 기록이 모두 `PASS`이고 90일 이내다.
- [ ] 배포 후보 범위 해시가 현재 코드와 일치한다.
- [ ] 실제 검토자가 최신 법령·지침 원문과 배포 후보를 확인했다.
- [ ] 기록에 개인정보, 상담·설문 원문, 비공개 법률 의견 전문이 포함되지 않았다.

`npm.cmd run legal:evidence:check`은 기록 형식·단계·기한·범위 해시만 검사합니다. 실제 검토의 품질, 법률 해석, 규제상 지위, 허가·신고 필요 여부는 검토 권한이 있는 사람과 기관이 판단합니다.
