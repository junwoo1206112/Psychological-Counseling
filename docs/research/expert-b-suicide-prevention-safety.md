# 전문가 B — 자살예방·위기개입 안전 설계 브리프

> 범위: 진단·치료가 아닌 **비의료 자가점검 앱**. 한국(2024–2026) 공식 자료 우선. 전화번호·운영시간은 출시 전·분기별 재검증 필수.

## 1. 핵심 결론

1. **선별은 그 자체로 개입이 아니다.** 긍정 선별 → 즉시 평가 → 연결(handoff) 경로가 없으면 위험하다. 결과 페이지 맨 끝에 번호만 두는 구조는 사실상 follow-up 없는 선별이다.
2. **PHQ-9 문항 9 단독 사용은 부적절.** 민감도는 높지만 특이도·PPV가 낮다. 반드시 자살사고 전용 문항(ASQ/C-SSRS)으로 확인한다.
3. 효과가 입증된 것은 **선별이 아니라 개입**이다: Safety Planning Intervention(SPI) + 구조화된 follow-up, lethal means counseling, caring contacts. **no-suicide contract(안전 서약)는 근거 없음**.
4. 앱의 핵심 개선 3가지: ① 모든 화면에 상시 위기 리소스, ② 현재 자살사고·계획·수단·과거 시도를 묻는 **즉시 위험 triage를 설문 초반**에, ③ Tier 3에서 **점수 표시 전 흐름 중단**.
5. 한국 번호: 2024-01-01부터 자살예방 상담은 **109**로 통합(1393 대체). **1577-0199는 폐지가 아니라 정신건강 위기상담으로 존속**, 1388(청소년), 1588-9191(생명의전화)도 존속. 129는 자살 핫라인이 아니라 **보건복지 상담**.
6. 법·윤리: 건강정보는 민감정보(별도 동의), 만 14세 미만 법정대리인 동의, 진단·치료·예방 효능 표현은 의료기기/SaMD 규제 리스크. "진단 아님"을 결과·공유·재방문 시 반복.

## 2. 근거: 작동하는 것 / 작동하지 않는 것 / 위험한 것

### 2.1 선별 도구
| 도구 | 구조 | 근거/성능 | 앱 역할 |
|---|---|---|---|
| **C-SSRS Screener** | 6문항(사고→계획→의도→행동), 12세+, lay 사용 | 광범위 사용·검증. 단, ED 퇴원 후 자살사망 예측 민감도 매우 낮음(30일 사망 Se≈0.18). **예측이 아니라 triage/severity** | Tier 판정 핵심 |
| **ASQ (NIMH)** | 4개 예/아니오 + 급성도 Q5, 20초 | 소아·성인 검증, Joint Commission 승인. Q1–4 중 하나라도 예 = 양성, Q5 예 = **imminent** | 가장 실용적. 1차 스크리너 |
| **PHQ-9 문항 9** | 죽는 게 낫겠다/자해 생각 빈도 | Na 2018: Se 87.6, Sp 66.1, **PPV 28.6**. 자살 위험 단독 선별 불충분 | 우울 점수용. item 9 ≥1이면 자살 모듈로 분기 |
| **PHQ-9/PHQ-2** | 9/2문항 | 우울 선별·치료 표준. 자살 예방 효과는 간접적 | 결과 설명용. **총점을 자살 위험 점수로 전환 금지** |

> 어떤 도구도 "누가 죽을지" 예측하지 못한다. 앱은 **"지금 안전한가"를 묻는 triage**로 설계하고, "위험 점수 87점" 같은 의사정밀도를 표시하지 않는다.

### 2.2 효과 있음
- **Safety Planning Intervention (Stanley–Brown, 6단계)**: ED 코호트에서 SPI+전화 follow-up이 6개월 자살행동을 약 절반(OR 0.45) 감소. 완성은 임상가와 함께가 원칙 — 앱은 작성 보조까지만.
- **Lethal means counseling**: 2024 체계적 문헌고찰 19개 중 14개에서 안전 보관 행동 개선. 단 근거 질 낮음(77% high risk of bias). 앱에서는 수단을 나열하지 않고 "쓸 생각이 있는 물건을 치우거나 맡기기" 수준.
- **Caring contacts**: 2023 메타분석에서 1년 자살시도 보호 효과, 자살사망은 불확실. 저비용·저위험. 앱은 opt-in 안부 알림만.
- **직접 묻기**: "자살을 물으면 유발한다"는 우려는 근거 없음(Gould 2005; DeCou 2017 메타; 2026 익명 평가). 안심하고 직접 물어도 된다.

### 2.3 효과 없음/위험
- **No-suicide contract**: 근거 없음, 책임 회피·낙인·비밀 유지 압력. Safety plan으로 대체.
- **선별만 하고 follow-up 없음**: "고위험입니다"만 알려주고 연결하지 않으면 harm 가능. 비유도 디지털 앱이 도움 요청을 오히려 줄일 수 있다는 질적 연구(2024).
- **자가진단 라벨링**: "당신은 중증 우울증입니다"는 CHI 2024 연구에서 혼란·낙인·무력감 유발.
- **위험 점수/ML 예측**: PPV 낮아 대규모 오탐. 비의료 앱의 자살 위험 예측 표방은 규제·윤리 리스크.

### 2.4 증거 공백
- 한국어 디지털 자가점검 앱의 RCT 근거는 사실상 없음.
- 앱에서 수단 접근을 직접 묻는 것의 이득/해악은 앱 특화 근거 부족.

- Tier 3은 한 문항이라도 해당 시 즉시 진입, 나머지 문항 중단.
- Tier 2/3에서 저장/공유 기본 off.
- "잘 모르겠다/말하고 싶지 않다"는 **양성으로 간주**.
- 음주/약물, 최근 상실, 수면박탈은 Tier 상향 modifier로만.

## 5. 권장 한국어 UI 문구

원칙: 직접적·비낙인·선택권 존중·구체적 행동. "극단적 선택", "자살 성공/실패", "왜 그런 생각을 했나요" 금지.

### 5.1 동의/면책 (첫 실행)
```
시작하기 전에 확인해 주세요

• 이 앱은 마음 상태를 스스로 점검해 보는 도구입니다.
  의학적 진단이나 치료를 대신하지 않습니다.
• 이 앱은 응급 상황을 자동으로 감지하거나 구조를 요청하지 않습니다.
• 답변은 [이 기기에만 저장됩니다 / 서버로 전송되지 않습니다].
  언제든지 삭제할 수 있습니다.
• 만 14세 미만이라면 보호자의 동의가 필요합니다.
• 원하지 않으면 언제든지 중단할 수 있습니다.

[동의하고 시작]   [먼저 도움받을 곳 보기]
```

### 5.2 사전 안전 문항 (설문 초반, 우울 척도보다 먼저)
```
지금 마음이 어떤지 먼저 여쭤볼게요.
답하기 어려우면 '잘 모르겠어요'를 눌러도 괜찮습니다.

1. 최근 2주 동안, 차라리 죽는 게 낫겠다는 생각이 든 적이 있나요?
2. 최근 2주 동안, 스스로 목숨을 끊고 싶다는 생각이 든 적이 있나요?
3. 지금 이 순간에도 그런 생각이 있나요?
4. 그런 생각을 하면서, 어떻게 하겠다는 계획을 세운 적이 있나요?
5. 지금 그 계획에 쓸 수 있는 물건이 손 닿는 곳에 있나요?
6. 예전에 스스로를 해치려고 했던 적이 있나요?
7. 지금 혼자서 안전을 지키기 어렵다고 느끼나요?
```
> 3번 예 → 즉시 Tier 3. 4·5·7번 예 → Tier 3. 6번 예 + 1·2번 예 → Tier 2 이상. 수단을 구체적으로 열거하지 않는다.

[119 구급]  [112 경찰]  [109 상담]

### 5.5 결과 에스컬레이션
**Tier 1**
```
죽고 싶은 마음이 가끔 들 수 있어요. 그 마음은 혼자 감당하지 않아도 됩니다.
지금 바로 109에서 이야기해 보시고, 가까운 정신건강복지센터에도 문의해 보세요.
```
**Tier 2**
```
지금은 전문가의 도움이 빠르게 필요해 보여요.
109 상담사와 지금 바로 이야기해 보시고, 믿을 수 있는 사람에게도 알려 주세요.
아래 안전 계획을 함께 만들어 두면 도움이 됩니다.
```
**Tier 3**
```
지금 바로 도움을 받아야 합니다.
119 또는 112에 연락하고, 혼자 있지 마세요.
가능하다면 지금 쓸 수 있는 물건을 다른 사람에게 맡기거나 손이 닿지 않는 곳에 두세요.
```

### 5.6 안전계획 (Stanley–Brown 6단계, 앱 버전)
```
나를 지키는 안전 계획

1. 나를 힘들게 하는 신호 (예: 잠을 못 잔다, 혼자 있고 싶다)
2. 혼자서 할 수 있는 대처 (예: 호흡, 산책, 샤워)
3. 나를 편안하게 해 주는 사람·장소
4. 연락할 사람 (이름 / 전화)
5. 도움을 요청할 곳 (109 · 1577-0199 · 1388 · 가까운 정신건강복지센터)
6. 안전한 환경 만들기 (쓸 수 있는 물건 치우기, 술 줄이기)

※ 이 계획은 전문가와 함께 점검할 때 더 효과적입니다.
[저장]  [믿을 수 있는 사람에게 공유]  [109와 통화]
```

### 5.7 "진단 아님" 문구
```
이 결과는 의학적 진단이 아닙니다.
우울증이나 자살 위험을 확정하지 않으며, 치료를 대신하지 않습니다.
정확한 평가는 의사 또는 정신건강전문가와 상담이 필요합니다.
```

### 5.8 청소년/보호자
```
만 14세 미만이라면 보호자의 동의가 필요합니다.
보호자에게 알리는 것이 안전하지 않다고 느껴진다면, 1388(청소년전화)에서 먼저 이야기해 보세요.
```

## 6. Safety do/don't

### DO
- 직접 묻는다: "죽고 싶은 생각이 있나요?"
- "이야기해 줘서 고마워요. 어려운 이야기였을 텐데요."
- 선택권을 준다: 통화/문자/방문/신뢰 인물.
- 구체적 다음 행동(번호, 버튼, 시간, 장소)을 제시.
- 리소스를 반복: 상단 배너 + 결과 + 저장/공유 + 재방문.
- 수단 접근을 낮춘다: "쓸 수 있는 물건을 치우거나 맡기기".
- follow-up 설계: opt-in 안부 알림, 2주 후 재점검.
- 문해력·접근성: 큰 글씨, 스크린리더, 색상 외 텍스트.
- 임상·이용자 자문, 카피 파일럿.

### DON'T
- "극단적 선택", "자살 성공/실패", "자살 충동에 이겼다" 금지.
- 방법·도구·장소를 구체적으로 묻거나 나열하지 않는다.
- "약속해 줘"(no-suicide contract) 금지.
- "왜 그런 생각을 했어요?", "그럴 만한 일이 없는데" 금지.
- "너만 힘든 게 아니야", "긍정적으로 생각해" 금지.
- 죄책감 유발("가족이 슬플 거야") 금지.
- "당신은 우울증입니다/고위험군입니다" 라벨 금지.
- 위험 점수·퍼센트·등급 표시 금지.
- 자동 보호자 통보 금지.
- 절대적 비밀 보장 약속 금지.
- 위기 화면에 광고·구독 유도 금지.

## 8. 구현 노트 (Expo/React Native + Web)

### 화면 순서
1. Splash + 연령 게이트
2. 동의/면책(짧게, 상세 expandable)
3. 사전 안전 문항 7개(현재 사고 우선)
4. 분기: Tier 3 → 즉시 crisis interstitial(설문 종료), Tier 2 → 짧은 확인 후 결과, Tier 0/1 → PHQ-9
5. PHQ-9(item 9 포함). item 9 ≥1 → 자살 모듈 재확인
6. 맥락 문항(수면·음주·고립·최근 상실) — 점수 가산 금지
7. 결과 + 안전계획 + 리소스
8. Follow-up opt-in

> 고위험 사용자에게 9문항 우울 척도를 먼저 풀게 하지 않는다. **안전 문항이 먼저.**

### 중단 규칙
- Q3(현재 사고) 예 → 즉시 중단.
- Q4·Q5·Q7 예 → 즉시 중단.
- Q6(과거 시도)+Q1/Q2 예 → Tier 2, 결과 상단 crisis banner.
- "잘 모르겠어요/건너뛰기" → 양성 처리.
- Tier 3에서는 PHQ-9 총점·백분위·"우울 위험" 표시 금지.

### 결과 페이지 필수 요소
- 상단 고정 crisis banner(109/119/112)
- "진단 아님" 문구(접기 불가)
- Tier별 메시지 + 주 행동 1개
- 109 원터치 통화, 119/112 보조
- 1577-0199·1388·1588-9191·정신건강복지센터 찾기
- 안전계획(작성/저장/공유)
- 신뢰 인물 연락, 수단 치우기 안내
- "상황이 나빠지면" 재안내, 하단 리소스 반복
- 저장/공유 opt-in, 공유 시 민감정보 제거

### 기술·UX
- 전화 링크: RN `Linking.openURL('tel:109')`; Web `<a href="tel:109">`. 자동 발신 금지.
- 통화 불가 환경: 번호 복사 버튼 + "109를 눌러 주세요".
- 문자/카카오: 마들랜 안내 URL(https://www.129.go.kr/109/etc/madlan).
- 오프라인: 리소스 JSON 번들 포함, `lastVerified` 필드.
- 알림: caring contacts opt-in, 알림 텍스트에 위험 내용·점수 금지.
- 다국어: 한국어 우선, 확장 시 문화적 타당성 검토.
- QA: 임상가·당사자 자문, red-team, 다크패턴 점검, 스크린리더 테스트.
