# 마감 전 최종 A/B/C 검토 — 2026-11-07

## 판정

코드·정적 웹 빌드·합성 브라우저 흐름은 **조건부 통과**다. 그러나 이 판정은 임상 효능, 실제 위기 전화 연결, 보조기술 적합성 또는 법적 배포 승인을 뜻하지 않는다. 한국어판 타당화, 독립 전문가 검토, 수동 접근성/실기기 시험, 법무·임상 운영 증빙이 없으므로 **임상·상업·공개 운영 배포는 아직 승인할 수 없다**. `release:ready`의 차단은 유지한다.

## 범위와 실제 확인

- 전체 코드·기존 연구/Seed/phase log·배포 Nginx 구성을 재검토했다.
- Chromium 실제 정적 웹 화면에서 초기 동의·연령·위기 배너·빠른 나가기와 접근성 트리를 점검했다. 초기 화면의 제목, 선택지, 위기 연락 행동은 노출됐고 화면상 중대한 배치 문제는 발견하지 못했다.
- 합성 입력만으로 정적 빌드의 설문 안전 흐름을 Playwright로 실행했다. 실제 자살위기 사용자, 전화, 외부 기관, 스크린리더/모바일 기기는 시험하지 않았다.

## A/B/C 교차검증과 반영

| 관점 | 확인한 문제 | 이번 반영 | 남는 사람 검토 |
|---|---|---|---|
| A — 임상·심리측정 | 희소 배열이나 잘못된 연령 값이 결과 생성에 들어가면 신뢰할 수 없는 낮은 결과가 될 여지가 있었다. 한국어 UI는 도구의 한국어 임상 타당화처럼 읽힐 수 있었다. | 결과 생성은 정확한 문항 수의 실제 정수 응답과 `adult`/`youth`만 수용한다. 시작/결과 문구를 ‘원 도구 기반 자가 선별’ 및 한국어 웹 사용의 미타당화 상태로 명확히 했다. | PHQ-9/PHQ-A/GAD-7 한국어 번역·웹 맥락의 정식 타당화와 독립 임상 검토. |
| B — 위기·자살예방 | 도움을 먼저 원하는 사용자를 설문에 묶지 않아야 하며, ASQ 마지막 급성도 문항에서 뒤로 가기는 ASQ Q4로 돌아가야 한다. | 도움 요청은 즉시 `/resources`로 이동하며, ASQ Q5의 이전은 Q4로 복귀한다. 위기 화면 안전 문구는 처방 약물 중단을 암시하지 않게 조정했다. | 실제 전화/기관 연결, BSSA 후속평가·운영책임, 위기 시 사용성 시험. |
| C — 구현·프라이버시·배포 | 결과 세션에 모순된 ASQ/위험 조합이나 렌더 불가 reason 객체가 들어올 수 있었다. Nginx location의 `add_header`는 상위 보안 헤더 상속을 끊을 수 있었다. | 세션 요약의 위험 구조·ASQ 조합·문자열 사유를 엄격 검증했다. PWA 특수 파일에는 location-level `add_header` 대신 `expires -1`을 사용했다. | 실제 Nginx/TLS 응답, 기존 탭 PWA 갱신, 의존성 major 업그레이드와 배포 후보 통합 E2E. |

## 이번 코드 보완

1. 결과 생성의 희소/범위 밖 응답과 누락·오류 연령대를 거부했다.
2. 결과 전달 세션에서 모순된 ASQ 양성/낮은 위험, 잘못된 risk 구조, 비문자열 사유를 거부했다.
3. 도움 우선 흐름과 ASQ Q5 뒤로 가기 흐름을 수정하고 브라우저 회귀 검사로 고정했다.
4. 자원 화면의 전화 실패 안내에 직접 번호·공식 안내 링크를 제공했다.
5. PWA 특수 파일이 상위 CSP·X-Frame-Options 보안 헤더를 상속하도록 Nginx 구성을 수정했다.
6. 저장 고지를 실제 저장되는 비채점 기능손상 수준까지 일치시켰다.

`npm.cmd run release:ready`는 정적 자원·프라이버시·저장 경계·CSP/빌드·PWA 감사까지는 통과했고, 아래 사람 증빙 레지스트리가 비어 있어 **의도대로 BLOCKED** 됐다. 이는 실패를 숨긴 것이 아니라 공개 배포를 막는 정상 안전장치다.

## 아직 닫히지 않은 배포 게이트

P0 (공개/임상 배포 전 필수):

1. 한국어 타당화 계획의 실제 연구·독립 임상 승인.
2. 현 배포 범위에 대한 독립 A/B/C 검토 증빙.
3. NVDA, VoiceOver, TalkBack, 320px/200%, 실제 전화 앱, 오프라인 위기 안내의 수동 기록.
4. 법무·규제 검토와 훈련된 임상가의 후속연결/BSSA 운영 증빙.
5. 운영 환경에서 TLS·CSP·PWA·기존 탭 갱신을 포함한 배포 후보 확인.

P1/P2 (별도 Seed 권장):

- Expo 56 production dependency 감사에서 보고된 취약점은 Expo 58 major 업그레이드를 요구하는 항목이 있다. 위기 흐름 수정과 묶어 자동 업그레이드하지 않는다.
- 배포 스크립트 후보 검증에 Playwright E2E를 포함하고, 초기 Nginx 설정 스크립트가 TLS 구성을 덮어쓰지 않는지 운영 환경에서 검토한다.
- 릴리스 전환 뒤 기존 탭의 해시 자산/PWA 갱신을 실제 기기로 시험한다.
- PHQ 결과 카드의 시간 표현과 위험 요약의 기간 표현은 임상 책임자가 최종 문구를 승인한다.
