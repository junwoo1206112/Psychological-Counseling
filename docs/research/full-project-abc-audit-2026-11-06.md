# 전수 A/B/C 교차검증 감사

검토일: 2026-11-06 (Asia/Seoul)  
방법: 프로젝트 로컬 Ouroboros interview Path C. 저장소의 실행 코드·테스트·배포 구성·문서와 공식 웹 자료를 A(임상·심리측정), B(위기안전), C(구현·프라이버시·배포) 관점으로 대조했다. 이는 실제 정신건강 전문가 자문, 임상시험, 법률 자문 또는 규제 승인이 아니다.

## 결론

**프로젝트는 우울·불안 증상과 자살 관련 신호를 선별하고 사람·기관으로 연결하는 목적에는 대체로 부합한다. 전면 재작성은 권하지 않는다.**

이 앱은 상담을 제공하거나 정신질환 전반을 진단·배제하는 제품이 아니다. 실제 임상·상업 배포는 한국어 타당화, 임상가가 참여하는 양성 후 평가·연결 운영, 법무·규제 게이트가 완료될 때까지 보류해야 한다. 코드 수준의 남은 개선도 있다.

## 범위와 검증 방법

- 검토: `app/`, `components/`, `data/`, `lib/`, `public/`, `deploy/`, `bin/`, `tests/`, `docs/`, 패키지·앱 설정.
- 제외: `node_modules/`, 생성물 `dist/`, 별도 Ouroboros 체크아웃과 모든 전이 의존성의 전수 보안 감사.
- 실행: `validate`, `test`, `a11y`, `skill:check`, 웹 정적 빌드, `git diff --check`.
- 웹 근거: NIMH ASQ, PHQ Screeners 이용 조건, 보건복지상담센터 109, 식약처 안내를 재확인했다.

## A/B/C 결과

| 주제 | A — 임상·심리측정 | B — 위기안전 | C — 구현·프라이버시 | 결론 |
|---|---|---|---|---|
| 척도와 점수 | PHQ-9/PHQ-A/GAD-7을 분리 합산하고 독자 복합점수가 없음 | PHQ 문항9 단독 판단을 피하고 ASQ를 병행 | 문항·해시·밴드·회귀 검사가 있음 | 유지 |
| 한국어 사용 | 현재 번역은 비공식이며 영문 합산 규칙이 타당화를 대체하지 않음 | 오해를 줄이는 고지 필요 | `translationStatus=unofficial`을 기록 | 임상·상업 배포 차단 요건 |
| ASQ | NIMH 자료는 의료 환경용이고 양성 후 훈련된 임상가의 추가 평가를 설명 | 급성은 결과보다 위기 화면 우선 | Q5 급성 라우팅과 결과 차단 구현 | 연결 안내까지만 제공한다고 명시 |
| 고민 탐색 | 비채점 탐색은 가능, 임상 점수 합산 불가 | 탐색 답변으로 위험도를 낮추면 안 됨 | 답변을 점수·저장에 넣지 않음 | 현 설계 유지 |
| 데이터 | 임상 근거 연구에는 별도 동의·보호 필요 | 안전계획 메모는 민감한 기기 내 데이터 | 서버·분석 SDK·응답 URL 전달을 찾지 못함 | 로컬 전용 유지 |
| 배포 | 진단·치료 표현을 피해야 함 | 위기 자원 최신성·실제 연결 확인 필요 | 정적 PWA·Nginx 구성은 있으나 배포 게이트 미완 | 운영 준비가 필요 |

NIMH는 ASQ 양성 후 훈련된 임상가가 Brief Suicide Safety Assessment를 하도록 안내한다. 현재 앱은 해당 평가를 대신하지 않고 전화·기관 안내를 제공한다는 한계를 유지해야 한다. [NIMH ASQ Toolkit](https://www.nimh.nih.gov/research/research-conducted-at-nimh/asq-toolkit-materials)

PHQ/GAD-7 자체보고는 임상가가 이해도와 다른 정보를 포함해 확인해야 하며, 확정 진단은 임상적으로 내려야 한다는 이용 조건과도 현재의 ‘선별’ 포지셔닝이 맞는다. [PHQ Screeners terms](https://www.phqscreeners.com/terms)

## 확인된 강점

1. 급성 안전 신호와 ASQ Q5 양성은 일반 결과보다 `/crisis`를 우선한다.
2. PHQ 문항9의 비영 응답은 이제 `low`로 종결되지 않고 빠른 도움 안내로 이어진다.
3. 설문 앞 고민 탐색은 선택·비채점이며 점수·세션 요약·기록 저장에서 제외된다.
4. `localStorage` 및 세션 저장소 차단, 손상·모순 요약, 삭제 실패를 방어한다.
5. 결과 URL에 원 응답을 넣지 않고, PWA·오프라인 위기 안내·기본 접근성·빠른 나가기·선택 저장이 있다.
6. 109, 1577-0199, 1388과 관련 상담·연계 정보는 공식 109 페이지의 현재 안내와 일치한다. [보건복지상담센터 109](https://www.129.go.kr/109/index.do)

## 페이즈별 기록

### Phase 0 — Inventory

실행 코드·문서·테스트·PWA·Nginx·배포 스크립트를 목록화했다. 기존 작업 트리는 대규모 미커밋 변경 상태이므로 감사 외의 코드 변경은 하지 않았다.

### Phase 1 — Interview / 목표 확인

확정된 제품 목적은 ‘선별 + 전문가 연결’이다. 자유대화 AI 상담, 자동 진단, 치료 권고, 서버 수집, 독자 임상 점수는 범위 밖이다.

### Phase 2 — A/B/C 교차검증

세 관점 모두 기존 구조를 보존해야 한다는 데 일치했다. 충돌 지점은 ‘현재 앱의 자원 안내를 실제 전문 상담 연결로 볼 수 있는가’였고, 운영상 인수·평가가 없으므로 **안내**로만 표현하는 것으로 해소했다.

### Phase 3 — Seed 상태

기존 AC1~AC41은 코드 검증 범위에서 완료 상태다. 이 감사에서 제시한 P0~P2는 새 사이클의 후보이며, 별도 Seed 승인 전에는 구현하지 않았다.

### Phase 4 — Implement

이번 감사에서는 제품 코드를 변경하지 않았다. 발견 사항은 다음 구현 사이클의 수용 기준으로만 기록했다.

### Phase 5 — Evaluate

| 명령 | 결과 |
|---|---|
| `npm.cmd run validate` | PASS |
| `npm.cmd test` | PASS, 53/53 |
| `npm.cmd run a11y` | PASS, 정적 감사 |
| `npm.cmd run skill:check` | PASS |
| `npm.cmd run build:web` | PASS, 정적 라우트 9개 |
| `git diff --check` | PASS |

코드 검색에서는 분석 SDK, 원 응답의 네트워크 전송, 콘솔 응답 로그를 발견하지 못했다. 단, 이는 의존성·브라우저 런타임 전체 보안 감사가 아니다.

### Phase 6 — Evolve

다음 최고 영향 순서는 다음과 같다.

1. 임상·상업 배포가 필요하다면 한국어 타당화와 기관·임상가 후속평가 운영을 먼저 확정한다.
2. 일반 통화 버튼 실패 처리와 손상된 결과 추이 데이터 방어를 구현한다.
3. 배포 파이프라인의 검증·HTTPS 게이트와 실제 기기 접근성/E2E 검증을 추가한다.
