# 목적 적합성·임상 안전성 A/B/C 교차검증

검토일: 2026-11-06 (Asia/Seoul)  
방법: 프로젝트 로컬 Ouroboros interview Path C. A(임상·심리측정), B(위기안전), C(구현·프라이버시)를 독립 에이전트로 검토하고 주 에이전트가 코드·재현 결과·공식 자료를 종합했다. 실제 임상 전문가 면담, 의료적 승인 또는 법률 자문은 아니다.

## 1. 결론

**목적에 부분 부합하지만, 현재 상태로 목적 달성 또는 배포 준비 완료라고 판정할 수 없다. 전면 삭제·재작성은 권하지 않는다.**

현재 앱은 우울·불안 증상과 자살 관련 신호를 설문으로 확인하고 연락처·기관 검색을 안내한다. 사용자가 기대하는 고민 탐색·상담 과정은 없고, 정신질환 전반의 조기 발견도 검증하지 않았다. 척도별 점수·급성 우선 분기·무백엔드·선택 저장 기반은 보존 가치가 있다. 전체 코드를 새로 써도 문항 타당성 및 실제 전문가 평가·연결 체계는 확보되지 않는다.

기존 HANDOFF 및 phase-log의 **“코드로 구현 가능한 릴리스 결함 소진” 판정은 이번 감사 결과로 철회**한다. 아래 결함은 미수정 상태다.

## 2. 사용자 인터뷰와 제안의 구분

사용자 원문:

> 웹과 자료를 바탕으로 너가 전문가급 지식인이 되어 문제를 직접 만들어 사람들의 심리 상담을 하여 이사람이 상태 점수에 따라 상황을 나누고 이제 전문가의 상담을 받아라는 식으로

확인된 의도: 질문으로 사용자의 심리 상태를 파악하고, 점수에 따른 설명과 전문가 상담 권고를 제공한다. 목적에 맞지 않으면 전면 재작성도 허용했다. 이는 반드시 삭제하라는 지시는 아니다.

**권장 설계(아직 승인된 새 Seed가 아님):**

1. 직접 설계하는 비채점 질문으로 고민, 일상에서 어려운 점, 받고 싶은 도움을 선택하게 한다. 건너뛰기와 설문 없이 도움받기 경로를 제공한다.
2. 상태 점수는 정확한 버전·이용조건·대상 집단을 확인한 검증 척도로만 계산한다. 비채점 답변이나 자유서술을 숨은 가중치로 점수에 합치지 않는다.
3. 우울·불안 척도별 수준과 안전 신호를 분리한다. 낮은 증상 점수가 다른 정신질환의 부재나 안전을 의미하지 않도록 설명한다.
4. 안전 신호가 있으면 일반 결과보다 안전 확인·사람에게 도움받는 경로를 우선한다. 앱이 임상가의 안전성 평가를 완료했다고 표시하지 않는다.
5. 결과는 진단 대신 응답 요약·척도별 수준·다음 행동·전문가에게 설명할 내용을 제공한다. 연결 기능의 실제 범위가 전화/검색 안내라면 그대로 표시한다.

웹 지식으로 자체 문항을 만들 수 있다는 것과 그 문항의 점수로 임상적으로 타당한 분류를 할 수 있다는 것은 다르다. 독자 점수·절단값을 도입하려면 내용타당도, 신뢰도, 준거타당도, 대상별 성능·위해 검토가 필요하다. 본 감사에서는 자체 임상 점수 체계를 만들지 않았다.

## 3. 범위·검토 방법

- 읽은 자료: HANDOFF, AGENTS, README, SKILL, A/B/C 연구 브리프, 기존 교차검증, Seed·phase-log, 한국어 타당화 및 법무 문서.
- 구현 검토: app, components, data, lib, public, deploy, tests, bin, 앱·패키지 설정. 실행 제품의 일차 소스와 검증 경로를 대상으로 했다.
- 별도 도구 체크아웃 `ouroboros/`, 복제된 `Codex_AI_스킬/`, 모든 전이 의존성을 전수 보안 감사한 것은 아니다.
- 공식 웹 자료와 원연구를 사용했다. 실제 상담·임상시험·실기기 스크린리더·브라우저 전체 E2E·실제 전화 연결은 수행하지 않았다.
- 기존 대규모 미커밋 작업을 보존했다. 감사 문서 및 인수인계 기록만 변경했다. 검증 중 dist가 재생성되었다. 커밋·푸시·배포는 하지 않았다.

## 5. 발견 사항

P1은 다음 배포 전 우선 해결, P2는 정확성·예외처리·고지 개선을 뜻한다. 임상적 긴급도 등급이 아니다. 파일 줄 번호는 감사 당시 기준이다.

### P1-1. 죽음·자해 관련 비영 응답이 낮은 수준으로 종결됨

- 위치: `data/instruments.js:502`, `app/result.js:111`.
- 조건: PHQ 문항9=1, 나머지 문항=0, 안전 확인과 ASQ 전부 아니요, 기능손상 없음.
- 실제 결과: 우울 합계 1, `risk.tier=low`. 결과 화면에는 ASQ 음성에 대해 급성 위험이 낮다는 설명도 나온다.
- 문제: 작은 보충 문구와 안전계획 메모만으로 상단 낮음 안내와의 모순이 해소되지 않는다. 모든 비영 응답은 추가 안전 확인 대상으로 다루되 자동으로 급성이라고 단정해서도 안 된다. 임상 경로 원연구 [S3]와 대조가 필요하다.

### P1-2. 저장소 접근 차단이 핵심 화면에 예외를 전파함

- 위치: `lib/storage/safety-plan.js:14`, `lib/storage/adapter.js:3`, `app/crisis.js:18`, `app/result.js:55`.
- `window.localStorage` getter가 예외를 던지면 try에 들어가기 전에 `loadSafetyPlan()` 등이 실패한다. Node getter 모의로 재현했다.
- 선택적 저장 기능 실패와 위기 안내 표시를 분리해야 한다. 실제 브라우저 화면 실패 형태는 추가 E2E로 확인해야 한다.

### P1-3. 동의·연령 게이트가 직접 URL에서 우회됨

- 위치: `app/survey.js:53`.
- 연령 누락을 adult로 처리하고 youth 이외의 값도 성인 척도를 사용한다. `/survey`, `/survey?ageGroup=child` 진입에 별도 동의·연령 가드가 없다.
- 실명 인증 요구가 아니라 정상 직접 진입에서도 시작 절차를 유지해야 한다는 결함이다.

### P1-4. 제품의 측정 타당성과 범위가 과장될 여지

- 위치: `app/index.js:23`, `data/instruments.js:69`, `app/survey.js:63`, 한국어 타당화 계획.
- 비공식 한국어 문항이 기본 노출된다. “영문 원문 기준 채점”은 숫자 합산 규칙 설명이며 응답 언어의 타당성을 보장하지 않는다.
- 기존 한국어 타당화판의 정확한 문항·대상·권리부터 확인하는 것이 자체 연구 재시작보다 우선이다. 기존 한국어 GAD-7 연구 [S7]가 있다고 해서 현재 앱의 다른 번역까지 타당화된 것은 아니다.
- 임상·상업 사용 불가라는 저장소 정책과 실제 첫 화면 설명을 맞춰야 한다. 우울·불안 점수로 정신질환 전반을 배제할 수 없다.

### P2-1. 불완전 입력과 손상 세션의 방어가 부족함

- 위치: `data/instruments.js:429` 이후 채점 함수, `lib/assessment-session.js:21`, `app/result.js:60`.
- 빈 응답을 채점하면 0/음성으로 취급하고 `buildAssessmentResult({})`는 low를 생성한다. 정상 설문 UI는 응답을 요구하므로 현재 일반 경로에서 결측이 발생했다는 뜻은 아니다.
- 우울=-5, 불안=999, `asq.acute=true`, `risk.tier=low`인 모순 요약을 `isAssessmentSummary`가 수락함을 재현했다. 결과의 급성 가드는 tier만 본다.
- 필수 응답, 정수·범위, 양성 후 급성도 확인 여부, 요약 필드·안전 신호 일관성을 검사해야 한다.

### P2-2. 삭제 실패를 성공으로 표시함

- 위치: `app/resources.js:57`, `app/history.js:60`.
- 삭제/저장 함수의 실패 반환을 무시하고 화면부터 비운다. 새로고침하면 남은 민감 기록이 다시 나타날 수 있다.
- 영구 저장 성공 여부에 맞춰 UI와 실패 안내를 갱신해야 한다.

### P2-3. 저장 고지와 실제 저장 범위 불일치

- 위치: `lib/assessment-session.js:49`.
- 세션 요약에 PHQ 문항9의 원응답과 기능손상 선택이 포함된다. “문항별 응답 제외”라는 고지와 엄밀히 맞지 않는다.
- 필요한 안전 플래그로 최소화하거나 고지를 정확히 해야 한다. QuickExit는 외부 이동이며 기존 저장 데이터·방문 기록 삭제 기능이 아니다.

### P2-4. 자체 안전 정책과 원 도구를 구분해야 함

- 위치: `data/instruments.js:102` 이후, `:110`, `:347` 이후 행동 안내.
- 사전 안전 4문항은 자체 구성이다. 기간 없는 과거 계획 질문을 항상 급성 경로로 보낸다. 보수적 안내 정책을 검증된 임상 판정과 구분해야 한다.
- PHQ 15~19점 카드의 수일 내 평가와 상단 routine의 2주 내 상담 안내가 다르다. 시한은 검증 척도 자체의 속성으로 제시하지 말고 근거 있는 운영 정책으로 일치시켜야 한다.

### P2-5. 실제 연결과 검증 범위 부족

- `components/CrisisBanner.js`의 링크 실행 실패를 조용히 무시한다. 통화 불가 시 피드백·다른 접근 경로가 필요하다.
- `app/centers.js`는 지역과 무관하게 같은 포털을 연다. 화면은 재선택 필요를 고지하지만 기관 연결 완료 기능은 아니다.
- `app/crisis.js` 직접 진입에서도 상담·자동 구조 요청 기능의 한계를 알 수 있도록 짧게 표시할 필요가 있다.
- release 테스트 다수는 소스 문자열 검사다. 라우팅 결과 미렌더, 실제 센터 웹 동작, 키보드·스크린리더 접근성을 증명하지 않는다.
- 문항 해시는 현재 배열에서 동적으로 계산해 다시 비교한다. 독립된 승인 원본/고정 해시와 대조하는 변경 방지 검사는 아니다.
- 자동 배포 스크립트는 build만 실행한다. 검증 명령 및 TLS는 실제 배포 게이트로 별도 확인해야 한다.

## 6. 외부 근거와 기존 문서 정정 사항

- NIMH ASQ는 양성 선별 후 훈련된 임상가의 추가 안전성 평가(BSSA)를 설명한다. 연락처 표시만으로 그 평가가 완료되지는 않는다. 의료환경 연구 성능을 한국 일반인 무감독 웹앱에 그대로 적용할 수 없다. [S1]
- USPSTF는 우울 선별의 이익을 얻기 위해 양성 후 진단 평가 및 적절한 근거 기반 관리 연결을 강조한다. 성인 자살 위험 선별의 순이익은 근거 불충분이며, 이를 효과 없음 또는 선별 금지로 해석해서는 안 된다. [S2]
- ASQ 한국어 공식 PDF(2017-05-04) Q3는 코드와 같은 ‘지난 몇 주’이고, 같은 PDF 영어는 past week다. 2025-09-29 영어판은 거부 처리와 과거 시도 단독 양성 설명도 다르다. 한국어 문항을 임의 수정하지 않고 원본 버전·변형 정책을 기록한 뒤 확인할 사안이다. [S4, S5]
- `unknown` 보수 처리, 응답 거부, 미응답은 같은 개념이 아니다. 앱 정책을 최신 ASQ 원형과 동일하다고 주장하지 않는다.
- 기존 자료의 “디지털의료제품법 2026-01-24 시행”은 전체 법 시행일과 일부 유예 조항을 혼동한다. 식약처 안내는 법 시행을 2025-01-24로 명시하며 일부 시행령 조항은 2026-01-24다. [S8, S9]
- “의료기기 아님” 문구만으로 법적 해당 여부가 확정되는 것은 아니다. 제품 사용목적·실제 기능에 대한 검토가 남아 있다. 본 감사도 해당 여부를 판정하지 않는다.
- 과거 연구 문서의 성인만 대상, 저장 미구현 등은 현재 구현과 다르다. 과거 결정 기록과 현 상태를 구분해야 한다.

## 8. 다음 구현의 수용 기준 후보 — 미승인

1. 비채점 고민 탐색 질문은 건너뛸 수 있고 척도 점수에 영향을 주지 않는다.
2. 척도별 점수와 안전 신호를 분리하며, 문항9 비영 응답을 낮은 위험으로 종결하지 않는다.
3. 저장소 차단·쓰기 실패·손상 데이터에서도 위기 안내 접근이 유지된다.
4. 직접 설문 진입에도 동의·허용 연령 확인이 유지된다.
5. 삭제 실패를 성공으로 표시하지 않고 저장 고지와 실제 데이터가 일치한다.
6. 원도구·번역·버전·검증 상태를 구분하고 한국어판 미검증 상태를 명확히 알린다.
7. 낮은 점수로 다른 정신질환을 배제하거나 앱 상담·전문가 연결 완료를 주장하지 않는다.
8. 급성 결과 미렌더, 비급성 양성, 상충 응답, 직접 접근, 저장소 실패를 브라우저 동작 검사로 확인한다.
9. 기존 5개 검증 명령을 통과하고 실제 임상·접근성·법무 후속은 별도 미완료로 남긴다.
